# UI polish and visual parity

1. Identify the target: a reference image, screenshot, existing screen, design system, or explicit taste rules from the conversation.
2. Inspect the current UI in the browser, simulator, terminal, or rendered output.
3. Change the visible hierarchy first: layout, spacing, typography, contrast, motion, and control placement.
4. Preserve existing interaction and data behavior unless the task changes it.
5. Compare the result to the target with a screenshot or direct visual inspection, then iterate until the meaningful differences are resolved.

Report what now matches, what intentionally differs, and how to view it.
